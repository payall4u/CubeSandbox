## S5.5d.3a gateway neighbor reliability

实现 commit `52976d3b` 将 netlink gateway neighbor 的 context-aware probe/poll deadline 从 20ms
调整到 250ms。它仍短于外层 2 秒 CNI readiness deadline，不增加固定 sleep：一旦所有 gateway
MAC 出现立即返回；context 取消仍即时终止。永久缺失在 250ms 后失败，随后沿 adapter 既有
`rollbackPreparing` 释放 TAP、shared root 与 durable INTENT。

新增两项专项测试：

- delayed publication 在 16 次 neighbor read、至少 15×2ms poll 后成功，防止回退到旧 20ms；
- gateway 永久缺失在约 260ms 有界失败，adapter 自动 rollback，TAP 和 adapter record 均不存在。

## d.3b 设计边界（DEFERRED）

用户决定先验收当前可靠性修复，然后优先优化占串行关键路径主体的 Guest/vsock 冷启动与内存。
d.3b 保留以下设计边界，仅当 Guest 优化后并发门禁仍受 network→VMM 串行依赖阻塞时恢复实施。

优先方案 A：RuntimeResource 在 CNI 地址/路由已知且 TAP 创建后发布 early attachment/FD，让 VMM
带 virtio-net 启动；gateway neighbor 解析、TC redirect 和 durable network commit 与 Guest boot
并行，Guest `CreateSandbox` 注入 interfaces/routes/neighbors 前 join network committed。若早期 TAP
边界仍不能满足门禁，再使用方案 B：无 NIC preboot 后通过版本化 worker command 调用 Cloud
Hypervisor `VmAddNet` 热插。

无论方案 A/B，StartSandbox 成功返回前必须同时满足 VMM-ready 和 network-committed；任一分支
失败都取消另一分支并进入可恢复 rollback。RuntimeResource lease/attachment/TAP 仍由 Cubelet
唯一拥有，worker 不直接调用 Cubelet；CubeShim 继续作为唯一编排与 durable lifecycle owner。
