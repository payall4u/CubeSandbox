### S5.5d.2b：Host controller 批事务

- 新事务在任何 controller 外部写之前，一次提交四个 controller 的 canonical old/target 和
  owner identity（`PREPARED`）。
- 对四个 controller 幂等写 target 并逐项精确回读；全部成功后一次提交
  `CONTROLLERS_COMMITTED`。不得每步写前/写后重复 fsync journal。
- 恢复看到 PREPARED 时，每个实际值必须是 old 或 target；合法时按 owner 状态续做或回滚，
  出现第三值则进入 durable DEGRADED。旧 schema 的逐步 journal 继续可恢复。

验收：提交数量由 controller 路径 10 次降为 2 次；每个 write/readback failpoint、Shim/worker
kill 和 restart 都收敛；同一 reviewer `PASS` 后才进入 S5.5d.2c。

#### S5.5d.2b 实施与证据

实现 commit `49313e43` 保持 owner 状态机和外部 controller 写入之间的 crash consistency，同时
把新事务升级为 schema v2：

- 第一次 controller 外部写之前，用一个原子 `PREPARED` journal 记录四个 controller 的

  fence；生产与 cleanup consumer 共用 queue-wide `flock`，防止 stale cleanup 与新 owner 交错。
